Temporal: Workflow Đăng Ký Ở Đâu & Cách Hoạt Động

Giải thích trực quan vì sao Temporal Server không lưu code mà vẫn biết workflow có những gì, và cách giải thích chuẩn xác với Mentor.

⚠️ Tại sao câu nói trước đó bị Mentor bắt bẻ?

❌ Câu nói gây hiểu lầm:

"Phải có workflow điều phối để cập nhật activity mới cho worker khác làm tiếp"

  • "Workflow điều phối": Nghe như bạn tự viết một service/container trung gian ngồi giữa chỉ huy.
  • "Cập nhật activity mới": Nghe như phải có ai đó thủ công tạo hoặc push việc sang queue.
  • "Để worker khác làm tiếp": Nghe như các worker chuyền tay nhau, giao việc trực tiếp cho nhau.

✅ Bản chất thật trong Temporal:

  • Temporal Server mới là bộ não điều phối: Workflow chỉ là một hàm code mô tả thứ tự các bước.
  • Cơ chế Task Queue (Pull): Hàm workflow gọi execute_activity, Server tự tạo Activity Task vào Task Queue.
  • Worker độc lập 100%: Worker A và Worker B không biết nhau, chỉ cắm đầu pull task từ Task Queue của mình.
📍 Câu hỏi 1: Chỗ nào là chỗ đăng ký Workflow?

Temporal Server không hề lưu trữ code Python của bạn. Toàn bộ code Workflow và Activity được đăng ký trực tiếp trong tiến trình Worker khi khởi động:

Tiến trình Worker (Của bạn) Lưu Code Trong RAM

Khởi động worker bằng Python:

worker = Worker(
  client,
  task_queue="doc-queue",
  workflows=[DocWorkflow],
  activities=[ocr_act, split_act]
)
# RAM Worker giữ toàn bộ hàm code!
Long Poll (Hỏi việc)
Temporal Server Chỉ Quản Lý Task Queue

Server chỉ biết Tên chuỗi (String) & Queue:

[Task Queues]
- "doc-queue"

[State History]
- Workflow ID: "doc-123"
- Type: "DocWorkflow" (chuỗi)

🔄 Câu hỏi 2: Không lưu code, làm sao Server biết Workflow có gì để chạy?

Temporal Server dùng cơ chế "Hỏi - Đáp từng bước" (Workflow Task & Commands). Bấm vào từng bước bên dưới để xem sự phối hợp:

1. Client / API
POST /start-workflow Tên: "DocWorkflow"
2. Temporal Server
Nhận yêu cầu Tạo Workflow Execution
3. Worker (RAM)
Chờ việc (Polling) Hàm DocWorkflow sẵn sàng
Bước 1: User hoặc Web API gửi lệnh lên Temporal Server: "Hãy khởi động workflow có tên 'DocWorkflow' trên queue 'doc-queue'". Server chỉ ghi nhận tên chuỗi này vào Database.
💬 Cheat Sheet: Mẫu câu chuẩn để trả lời Mentor
"Workflow được đăng ký ở đâu trong hệ thống?"
Dạ, Workflow được đăng ký trực tiếp trong code khởi tạo của Worker (thông qua tham số workflows=[...]). Temporal Server không lưu trữ code này, nó chỉ quản lý Tên định danh và Task Queue.
"Temporal Server không có code thì làm sao biết lúc nào gọi activity nào?"
Dạ, khi chạy, Temporal Server gửi một Workflow Task cho Worker. Worker nạp hàm workflow trong RAM của nó ra chạy một đoạn code. Khi code đụng đến lời gọi execute_activity, Worker sẽ gửi lệnh (Command) về báo cho Server. Lúc đó Server mới biết và tạo Activity Task đẩy vào Task Queue.
"Các Worker có chuyển giao việc trực tiếp cho nhau không?"
Dạ không. Các Worker hoàn toàn độc lập. Mọi việc trao đổi đều thông qua việc Worker kéo việc (Poll) từ Task Queue do Temporal Server quản lý. Worker làm xong kết quả thì trả về cho Temporal Server, chứ các worker không hề biết sự tồn tại của nhau.
