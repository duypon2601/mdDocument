Temporal chạy thế nào trong dự án này

Mô phỏng một file PDF 25 trang scan đi từ lúc upload tới khi có vector. Mỗi token là một thứ đi qua lại giữa các container. Cột bên phải là lịch sử event mà Temporal Server ghi lại, giống tab Event History trong Temporal UI. Bạn có thể tắt worker giữa chừng để xem chuyện gì xảy ra. Phần lý thuyết chung xem ở trang giới thiệu Temporal.

Bấm Chạy để bắt đầu. Trong lúc chạy, bấm Tắt ở một worker để mô phỏng worker chết.

    Chỉ ghi thêm, không sửa dòng cũ.
      workflow task activity task kết quả dữ liệu, file signal Dòng tím trong code là chỗ workflow đang chạy, tím nhạt là chỗ đang await, cam là đang replay.

      Server không chạy code

      Temporal Server chỉ ghi lịch sử, giữ hàng đợi và đếm thời gian. Code workflow chạy trong Indexing Worker, code activity chạy trong Conversion Worker.

      Worker tự đi lấy việc

      Server không gọi tới worker. Worker liên tục poll hàng đợi của mình. Thêm một Conversion Worker là có thêm một bên lấy việc từ convert-tq, không phải cấu hình gì ở server.

      Workflow ngủ giữa các bước

      Sau mỗi await, workflow không chiếm worker. Khi activity xong, server tạo workflow task mới và worker chạy tiếp từ chỗ đó. Lúc chờ duyệt, workflow có thể nằm im nhiều ngày mà không tốn gì.

      Chết giữa chừng không mất việc

      Activity mất heartbeat thì server đưa lại vào hàng đợi cho worker khác. Indexing Worker khởi động lại thì đọc lịch sử và chạy lại code workflow (replay) để về đúng chỗ. Activity đã xong không chạy lại.

      Thử các tình huống

      • Tắt Conversion Worker #1 khi nó đang chạy ocr_pages. Việc quay lại convert-tq và #2 làm tiếp.
      • Tắt Indexing Worker khi đang OCR. OCR vẫn xong, nhưng workflow task nằm chờ trong ingest-tq. Bật lại để xem replay.
      • Tắt cả hai Conversion Worker. Việc dồn lại trong convert-tq cho tới khi có worker bật lại.
      • Tick OCR tin cậy thấp trước khi chạy để xem workflow chờ signal.

      Tên activity, hàng đợi và thứ tự các bước lấy từ packages/index/src/ingest/index/workflows/ingestion.py và packages/convert/src/ingest/convert/activities.py. Số lô, số chunk, thời gian và timeout là số minh hoạ. Mỗi worker ở đây chạy 2 việc cùng lúc cho dễ nhìn; cấu hình thật của Conversion Worker là 4. Giống Temporal thật, event ActivityTaskStarted chỉ được ghi khi activity kết thúc, kèm số lần thử.
