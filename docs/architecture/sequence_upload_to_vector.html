C4 Model • Level 2 Sequence Flow

Từ upload file đến lưu vector

Một tài liệu đi qua POST /documents, DocumentIngestionWorkflow và các activity convert, index cho tới khi vector nằm trong Qdrant và trạng thái là INDEXED. Mỗi participant ghi tên package chạy nó.

ingest-tq: workflow, update_status convert-tq: detect, parse, OCR, finalize index-tq: chunk, embed, cleanup

1

Nhận file

  • Code ở packages/api: app.py, validator.py, dedup.py, workflow_client.py.
  • API trả 202 ngay sau khi start workflow, không chờ xử lý xong. Người dùng hỏi tiến độ bằng GET /documents/{doc_id}.
  • Workflow id ingest-{doc_id} cùng policy ALLOW_DUPLICATE_FAILED_ONLY chặn việc start hai lần cho cùng một file.
2

Chuyển sang Markdown

  • Workflow ở packages/index/.../workflows/ingestion.py chỉ điều phối. Code convert nằm ở packages/convert/.../activities.py và được gọi theo tên qua convert-tq.
  • detect_format quyết định có bao nhiêu lô OCR. File html hay text có 0 lô, nên chỉ chạy parse_document.
  • Các bước truyền nhau key trên MinIO, không truyền nội dung file qua Temporal.
3

Chunk, embed, ghi vector

  • Code ở packages/index: activities.py, chunking.py, embedder.py, vectorstore.py.
  • embed_and_upsert tự đọc lô chunk từ MinIO và ghi thẳng vào Qdrant, nên vector không đi qua Temporal.
  • Point id sinh từ uuid5, nên retry một lô không tạo bản trùng.
Activity nào lỗi hết số lần retry thì workflow ghi FAILED kèm mã lỗi. Huỷ bằng POST /documents/{doc_id}/cancel thì ghi CANCELLED. Timeout và retry của từng activity xem bảng trong c4-model.md. Chi tiết riêng cho giai đoạn 2 và 3 xem sequence_phase2.html và sequence_phase3.html.
